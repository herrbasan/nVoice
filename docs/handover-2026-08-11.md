# Handover — Assistant dictation loop (2026-08-11)

## The product (what the user wants)

Hands-free dictation on the **Assistant** page (`/#page=assistant`):

```
"ok kimi listen" → dictation → "ok kimi stop" or "ok kimi send" → local LLM cleans the STT text
```

The **entire** product is this loop. NOT a chat assistant. NO TTS. NO conversation bubbles.
TTS + chat UI were removed on purpose (user: "I just want the kimi listen -> transcription kimi send workflow working. thats all.").

Cleaning = remove voice-command remnants ("ok kimi", "listen", "stop", "send"), fix Russian words
that STT misfires on, fix punctuation, preserve paragraph breaks.

## What works (verified)

- **Eager warmup at boot** (75efd6f): worker spawns at server start; `/v1/admin/status` shows `ready` before any client. First Start is instant. WS relays buffer frames during warmup.
- **Cleanup endpoint** `/v1/assistant/clean`: dirty STT → clean text. Verified:
  `"ok kimi listen please remind me to call the dentist at three pm стоп thanks"` → `"Please remind me to call the dentist at three pm."`
- **Paragraph preservation** (4fed029): `\n\n` in the input survives the LLM. Verified with 3-paragraph input — all 3 breaks preserved, command remnants removed.
- **Paragraph signal**: measured pause (gap since last final) → `pendingParagraph` flag → `\n\n` prepended to LLM input (after trim so a leading break survives). LLM told to preserve + refine by topic, never merge separated paragraphs.
- **Reset on listen** (f3e6f3b): "kimi listen" clears SDK dictation, sends `{type:'assistant_reset'}` over realtime WS → server clears committedText/pendingRaw/timers; page clears Raw + Cleaned panels. Verified live: server logs `Assistant session reset (kimi listen)`.

## ⚠️ RESOLVED — "ok kimi listen" not transcribing (38f6c8c)

**Root cause:** `_kimiToSleep()` called `this.sleep()` (set `isAwake=false`), cutting
audio to the STT. When the wake fired but parakeet hadn't yet produced a final within
the 4s command window, the timeout closed the audio gate. The STT never transcribed
"ok kimi listen", so the text-command fallback in `_kimiOnFinal` never got a chance.
The user had to repeat themselves until timing lined up.

**Fix (38f6c8c):** removed `this.sleep()` from `_kimiToSleep()`. Audio stays open.
The text-command fallback (`_kimiShouldTreatAsCommand`) catches late-arriving finals
on the next cycle. Explicit `stop`/`send` actions in `_kimiClassifyCommand` still call
`this.sleep()` directly — those are intentional user commands.

**Verified:** 11 full cycles on live system. 1 timeout (STT warmup latency), 10
successful classifications. Dictation across English/German, paragraph breaks, and
reset-on-listen all worked correctly.

## Architecture notes for the next model

- **Node is a relay only** — never decodes audio (G1). Browser→Node→worker WS, binary PCM.
- **Assistant WS session state** (`committedText`/`pendingRaw`/`pendingParagraph`) lives in the
  `wss.on('connection')` closure in `realtime.js` — resets on `assistant_reset` only. The
  socket stays open across kimi sleep/transcribe cycles, so state must be reset explicitly.
- **Kimi state machine** (sdk): `sleep` → `command` (capture next utterance) → `transcribing`
  (dictate) → back to `command` on interrupt. Commands matched locally via `_kimiMatchCommand`
  (priority stop > send > listen). `assistant_reset` is sent on `listen`.
- **Two cleanup paths**: live pause-cleanup (`cleanTranscript`, bounded tail, commits on
  terminal punctuation) and final `cleanDictation` → `POST /v1/assistant/clean`
  (`CLEAN_STT_PROMPT`, full text). Both must preserve `\n\n`.
- **Parakeet metadata is fake/empty** — `probability` hardcoded 1.0, no word timestamps. The
  only real signal for paragraphs is the measured pause gap. Don't feed parakeet "metadata"
  to the LLM.
